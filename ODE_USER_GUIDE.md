# ODE 0.21.1 — понятная инструкция пользователя

Эта инструкция — для инженера, который впервые открыл ODE на рабочем
Windows-ноутбуке. Здесь только практические действия: как запустить программу,
куда нажимать и что проверить перед сохранением.

> **Статус 0.21.1 RC:** это кандидат для физической приёмки на рабочем
> Windows-ноутбуке, а не утверждённый rollout. До заполнения
> `docs/MANUAL_TESTING_0_21_1_WINDOWS.md` статус Windows-приёмки — **PENDING**.

> **Главное правило:** сначала проверьте выбранный склад, S/N и Preview, затем
> нажимайте Confirm. Не редактируйте файлы `.db` вручную.

## Быстрый запуск за 3 минуты

1. Полностью распакуйте архив ODE в отдельную папку, например
   `C:\ODE_0.21.1`. Не запускайте программу прямо из ZIP. Архивы 0.21.0
   отозваны для повторного переноса.
2. Убедитесь, что на ноутбуке установлен Python 3.10 или новее.
3. Дважды щёлкните `start_windows.bat`.
4. Если браузер не открылся, перейдите на `http://127.0.0.1:8765`.
5. Для обычной работы нажмите **Начать работу**, укажите своё настоящее ФИО и
   войдите как инженер.
6. Откройте **Склад** и выберите площадку: **IXcellerate** или **Solar**.

Если при запуске видны `'3'`, `'cho'`, `'DE' is not recognized` или
`ModuleNotFoundError: baseline_rehearsal`, остановитесь. Не исправляйте файлы и
не трогайте `.db`: распакуйте 0.21.1 в новую папку по `README_WINDOWS.md`.

Если сверху есть заметная надпись **ТЕСТОВЫЙ КОНТУР**, вы работаете не с
рабочими данными. Это нормально для обучения, но результаты нельзя считать
реальными складскими операциями.

## Пять правил безопасной работы

1. **Всегда проверяйте площадку.** IXcellerate и Solar — разные физические БД.
2. **S/N — главный идентификатор.** Inventory Number не заменяет серийный
   номер.
3. **Preview — это проверка, Confirm — запись.** До Confirm исправьте все
   ошибки и сомнения.
4. **Не повторяйте Confirm после непонятной ошибки.** Сначала проверьте историю
   и сохраните текст ошибки.
5. **Не открывайте и не правьте `.db` вручную.** Перед переносом, обновлением
   или массовой операцией сделайте backup.

## Куда заходить

| Раздел | Для чего нужен |
|---|---|
| **Склад → Приход** | Принять оборудование, компонент или кабель |
| **Склад → Расход** | Выдать оборудование, списать компонент или кабель |
| **Склад → Баланс** | Посмотреть остатки и найти карточку позиции |
| **Склад → Поставки** | Загрузить поставку и принимать её по строкам |
| **Склад → Инвентаризация** | Сравнить фактические S/N с учётом |
| **Отчёты** | Работы за смену, УВР, передача по смене и Excel |
| **Мониторинг** | Найти hostname/DCIM-данные и подготовить текст инцидента |
| **База знаний** | Найти или добавить рабочую статью |
| **Отпуска** | Посмотреть календарь, заявки и конфликты |
| **Администрирование** | Пользователи, диагностика, аудит и backup |

Лупа в верхней части ODE выполняет общий поиск по S/N, Inventory Number,
hostname, модели, проекту, поставке и полке.

## Приход оборудования

Перед началом проверьте, что выбрана правильная площадка.

1. Откройте **Склад → Приход**.
2. Выберите подходящий режим: ручной ввод, сканер, кабель или поставка.
3. Заполните дату, ответственного, тип, вендора, модель, ЦОД и полку.
4. Отсканируйте или аккуратно вставьте S/N.
5. Проверьте временный список: S/N, количество, модель и место хранения.
6. Нажмите Confirm только после проверки всех строк.
7. Откройте историю или баланс и убедитесь, что позиция появилась.

Для оборудования один S/N означает одну физическую единицу. Повторный приход
того же S/N будет отклонён. Inventory Number можно назначить позже — новую
карточку для этого создавать не нужно.

## Расход оборудования или компонента

1. Откройте **Склад → Расход**.
2. Выберите сценарий: сканер, выбор из баланса, пары
   `компонент → целевое оборудование`, кабель, CSV или ручной ввод.
3. Укажите задачу/ИЗМ и ответственного.
4. Проверьте S/N выдаваемой позиции и, если есть цель, S/N/hostname целевого
   сервера или коммутатора.
5. Убедитесь, что позиция найдена и остаток больше нуля.
6. Проверьте Preview и только затем подтвердите расход.
7. Убедитесь в истории, что операция записана один раз.

Повторный расход уже выданного S/N и расход сверх остатка блокируются. Кабели
обычно учитываются по количеству или метражу и списываются из старых партий
первыми.

## Баланс и карточка позиции

- Используйте фильтры по категории, типу, вендору, модели, проекту, поставщику
  и площадке.
- Раскрывайте дерево `категория → тип → вендор → модель`.
- Щёлкните по найденному S/N, чтобы открыть карточку, Timeline и историю.
- Состав оборудования показывает только подтверждённые списания компонентов
  на целевой S/N. Он не гарантирует фактическое наличие или точный физический
  слот без отдельной подтверждающей записи.

Если нужная позиция не находится, сначала проверьте площадку и S/N без лишних
пробелов. Не создавайте вторую карточку «на всякий случай».

## Поставки, инвентаризация и массовые файлы

- Сначала загрузите документ и изучите Preview.
- Красные/конфликтные строки нельзя подтверждать без разбора причины.
- Массовое назначение Inventory Number ищет карточки только по S/N.
- Простая инвентаризация сравнивает списки и не меняет рабочую БД.
- Перед большим Confirm создайте backup.

CSV открывайте как UTF-8 с разделителем `;`. В Excel столбцы S/N и Inventory
Number должны оставаться текстовыми: длинный номер нельзя превращать в число
или экспоненту.

## Мониторинг: пошагово

1. Откройте **Мониторинг**.
2. Вставьте hostname и кратко опишите проблему.
3. Проверьте hostname и нажмите кнопку поиска только один раз.
4. Дождитесь результата и проверьте проект/ИС, ITSM, S/N, локацию, класс
   критичности и адресатов.
5. Прочитайте сформированный текст целиком.
6. Скопируйте текст в разрешённый канал только после ручной проверки.

ODE удаляет пробелы, табуляции и переносы из вставленного hostname. Поиск не
запускается сам. Письмо и Rooms-сообщение автоматически не отправляются.

Если DCIM не отвечает, не запускайте поиск много раз подряд. Проверьте Edge,
корпоративную авторизацию и сеть; затем сообщите сопровождающему точный текст
ошибки. API-ключ в ODE вводить не требуется.

## Отчёт за смену и передача

1. Откройте **Отчёты → Отчёт за смену**.
2. Укажите дату, источник, описание, раздел, статус, срок и комментарий.
3. Для PNR последовательно отметьте выполненные пункты чек-листа.
4. На вкладке **За смену** проверьте список и KPI выбранного дня.
5. На вкладке **Передача по смене** проверьте незавершённые задачи.
6. Перед передачей выгрузите нужный Excel и откройте его для проверки.

Импорт отчёта выполняется через Preview → Confirm и не создаёт складских
приходов или расходов.

## База знаний и отпуска

В **Базе знаний** используйте поиск и теги. Не прикладывайте пароль, cookie,
закрытый ключ или файл рабочей БД к статье.

В **Отпусках** проверьте площадку, период и конфликты перед сохранением заявки.
ODE не отправляет заявку во внешнюю систему автоматически.

## Резервная копия

Перед обновлением, переносом или массовой операцией:

1. войдите через отдельный **Вход администратора**;
2. откройте **Администрирование → Резервные копии**;
3. по очереди создайте snapshot нужных БД;
4. дождитесь успешных SHA-256, integrity, foreign key и schema checks;
5. запишите показанный путь к backup.

Restore из интерфейса отключён. Не заменяйте рабочую БД файлом вручную во
время работы ODE.

## Если что-то не работает

| Ситуация | Что сделать |
|---|---|
| Windows пишет «Python не найден» | Установить Python 3.10+ и включить `Add Python to PATH` |
| Браузер не открылся | Открыть `http://127.0.0.1:8765` вручную |
| Страница не загружается | Проверить окно ODE; не закрывать его во время работы |
| `401` | Войти заново: сессия отсутствует или истекла |
| `403` | Недостаточно прав; использовать правильный режим входа, а не чужую cookie |
| `429` | Подождать 15 минут после серии неверных паролей |
| S/N уже существует | Найти существующую карточку; не создавать дубль |
| Нет остатка | Проверить площадку и историю позиции |
| DCIM не отвечает | Проверить Edge, корпоративную сессию и сеть; не повторять поиск бесконечно |
| Ошибка после Confirm | Не подтверждать повторно; проверить историю и записать текст ошибки |

Для обращения к сопровождающему подготовьте:

- версию ODE;
- дату и точное время;
- выбранную площадку;
- раздел и действие;
- точный текст ошибки;
- скриншот без пароля, cookie и закрытых данных, если это допустимо.

## Как правильно завершить работу

1. Закончите незавершённый Preview или явно отмените его.
2. Выйдите из ODE.
3. Закройте вкладку браузера.
4. Вернитесь в окно запуска и нажмите `Ctrl+C`.
5. Дождитесь остановки процесса перед копированием или заменой файлов.

Для расширенного регламента используйте
[`docs/USER_GUIDE.md`](docs/USER_GUIDE.md). Инструкция по Windows находится в
[`README_WINDOWS.md`](README_WINDOWS.md).
