# ODE 0.21.0 — приватный перенос Monitoring на рабочий Windows-ноутбук

Private transfer ZIP содержит проверенный source ODE 0.21.0 и локальные
`data/monitoring/*.json`. Эти JSON могут включать внутренние hostname, проекты
и адресатов. Архив нельзя загружать в GitHub, публичное облако или личный
файлообменник; передача допускается только разрешённым корпоративным способом.

## Что отсутствует намеренно

- `data/warehouse.db` и `data/warehouse_solar.db`;
- `data/vacations.db`;
- test/candidate/backup SQLite-файлы и sidecar-файлы;
- XLSX-источники правил, отчёты анализа, персональные пути и credentials.

Архив не должен перезаписывать рабочие БД. Для обновления существующей
установки сначала остановите ODE, сделайте внешний backup трёх runtime-БД,
распакуйте пакет в новую папку и отдельно перенесите прежние DB после сверки
SHA-256. Не распаковывайте пакет прямо поверх запущенной рабочей папки.

## Проверка до запуска

1. Полностью распакуйте архив, например в `C:\ODE_0.21.0`.
2. Проверьте `SHA256SUMS.txt` и внешний SHA-256 самого ZIP.
3. Убедитесь, что в `data\monitoring` есть два JSON-файла, но нет `*.db*`.
4. Для optional live DCIM установите зависимости из
   `requirements-monitoring.txt` и настройте Microsoft Edge/WebDriver.

## Безопасная приёмка

Сначала запустите `start_test_windows.bat` и проверьте вход, навигацию и
рендеринг Monitoring. В форме Monitoring можно проверить очистку пробелов и
валидацию пустого hostname, но живой поиск выполняйте только позже на рабочем
ноутбуке с разрешённой корпоративной сессией. ODE не отправляет письмо или
Rooms-сообщение автоматически.

После Windows-проверки зафиксируйте версию Python, SHA архива, результат
запуска и SHA/integrity/FK рабочих БД до/после.
